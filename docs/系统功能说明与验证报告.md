## 一、系统概览

系统面向 AI+PBL 实训项目的师生双向互选，覆盖 **学生端 / 教师端 / 管理端**，完整流程为：

```
集中宣讲 → 开放日 → 志愿填报 → 面试 → 导师选人 → 学生终选 → 调剂分流（实训室内→全校）→ 多轮补录 → 待选池 → 公示入组
```

| 角色 | 角色码 | 演示账号 | 密码 | 可用功能前缀 |
|------|--------|----------|------|--------------|
| 学生 | 1 | S-A01 | 123456 | `/api/student/**` |
| 教师 | 2 | T-SD01 | 123456 | `/api/teacher/**` |
| 管理员 | 3 | admin | 123456 | `/api/admin/**` |

**访问地址**

| 服务 | 地址 |
|------|------|
| 前端 | http://127.0.0.1:5500/frontend/index.html |
| 后端 API | http://localhost:8080/api |
| Swagger | http://localhost:8080/swagger-ui.html |

**登录方式**：打开前端后出现登录遮罩，可输入账号密码，或点击三个「演示账号」快捷按钮一键登录。登录后顶栏仅显示当前角色入口，其他角色入口隐藏，不能直接切换；如需换角色请先退出登录。登录态使用 JWT，存于浏览器 localStorage，过期或失效会自动回到登录页。

## 二、学生端功能

学生端共 5 个页面，全部使用真实接口数据。

### 1. 流程概览
- 展示当前综合状态：未填报志愿 / 已提交志愿 / 面试中 / 等待老师选择 / 已被老师选中 / 待终选 / 已匹配 / 分流中 / 待选池 / 已安置。
- 展示当前轮次与阶段（志愿填报、面试、导师选人、学生终选、调剂分流等）、8 个流程阶段时间线。
- 汇总卡片：已选志愿数（最多 3）、调剂意愿、录取状态；若已匹配则显示导师、实训室、轮次与匹配来源。
- 接口：`GET /student/status`、`GET /public/flow`、`GET /student/choices`

### 2. 志愿填报
- 按实训室分组展示全部导师卡片：姓名、职称、研究方向、简介、名额上限与实时剩余名额（剩余紧张时有颜色提示）。
- 最多选择 3 名导师作为**平行志愿**（不分先后），支持移除；可设置调剂意愿：服从实训室内调剂、服从全校调剂（可多选/单选/不选）。
- 提交为全量覆盖式保存；仅「志愿填报」阶段可编辑，其他阶段会禁用并提示。
- 已录取或进入待选池的学生不可再提交。
- 接口：`GET /public/rooms`、`GET /public/teachers`、`GET /student/choices`、`POST /student/choices`

### 3. 面试安排
- 展示本轮各志愿导师的面试时间、地点、状态（待安排/已安排/已完成/已取消）、面试成绩与导师评价。
- 无面试记录时显示合理空态。
- 接口：`GET /student/interviews`

### 4. 导师确认（终选）
- 展示所有向你发出拟录取意向的导师（`pickers`）。
- 收到 2 位及以上意向时需要在规定时间内选择 1 位；仅 1 位时自动确认，无需操作。
- 提交终选立即写入匹配结果，页面刷新为已匹配。
- 接口：`GET /student/pickers`、`POST /student/final-choice`

### 5. 录取结果
- 已录取：展示实训室、导师、研究方向、匹配来源（正常匹配/调剂老师选择/系统统筹/待选池人工安置）、轮次与时间。
- 未录取：展示分流或待选池状态（约谈时间、安置老师、备注）。
- 接口：`GET /student/result`、`GET /student/status`

## 三、教师端功能

教师端共 4 个页面。

### 1. 招生概览
- 名额使用：名额上限、已录取、剩余名额、使用进度条；剩余紧张时提示。
- 本轮数据：选择我为志愿的候选生人数、本轮已选人数、调剂可选人数。
- 流程节点：学生填报、组织面试、选拔候选生、学生终选、调剂选生各阶段状态。
- 接口：`GET /teacher/profile`、`GET /public/flow`、`GET /teacher/candidates`、`GET /teacher/picks`

### 2. 候选人管理
- 只显示本轮选择了我作为志愿的学生：学号、专业、班级、志愿来源、面试平均分。
- 可安排面试（时间、地点），录入面试成绩与评价。
- 可在剩余名额内勾选学生（暂选），也可撤销；暂选不直接录取，等待学生终选或阶段结束自动匹配。
- 接口：`GET /teacher/candidates`、`GET /teacher/interviews`、`POST /teacher/interviews`、`PUT /teacher/interviews/{id}`、`GET/POST /teacher/picks`、`DELETE /teacher/picks/{studentId}`

### 3. 调剂选生
- 仅在调剂分流阶段可用：展示本轮未录取、服从调剂、且调剂范围包含我的学生（实训室内 / 全校），附平均分与调剂范围。
- 点击选择即**立即录取**，受剩余名额限制。
- 接口：`GET /teacher/diversion/candidates`、`POST /teacher/diversion/picks`

### 4. 录取名单
- 展示最终录取的全部学生，区分录取来源（正常匹配 / 调剂 / 统筹 / 人工安置）。
- 接口：`GET /teacher/students`

## 四、管理端功能

管理端共 6 个页面。

### 1. 数据总览
- 总览统计：学生总数、已匹配、未匹配、匹配率、待选池数量、各匹配来源人数、当前流程进度。
- 按实训室统计：导师数、名额总数、已录取、剩余。
- 「导出匹配结果 CSV」按钮：下载全部匹配记录（UTF-8 BOM，Excel 可直接打开）。
- 接口：`GET /admin/stats/summary`、`GET /admin/stats/by-room`、`GET /admin/stats/export`

### 2. 基础数据
- **实训室**：列表展示（名称、编码、描述、启用状态），支持新建、编辑（名称/编码/简介/启停）。
- **教师**：分页 + 关键词搜索（姓名/工号），展示所属实训室、职称、名额、账号状态；支持新建、编辑（含名额）、查看名额变动日志、启用/禁用账号、重置密码。
- **学生**：分页 + 关键词搜索，展示学号、专业、班级、账号状态；支持新建、编辑、启用/禁用账号、重置密码。
- 接口：`GET/POST/PUT /admin/rooms`、`/admin/teachers`、`/admin/students`、`PUT /admin/users/{id}/enabled`、`PUT /admin/users/{id}/reset-password`、`GET /admin/teachers/{id}/quota-logs`

### 3. 流程控制
- 查看全部轮次及 7 个阶段（志愿填报 → 志愿关闭 → 面试 → 导师选人 → 学生终选 → 调剂分流 → 完成）的状态。
- 「开始轮次」：初始化阶段并开放志愿填报。
- 「进入下一阶段」：按顺序推进；推进过「学生终选」时自动处理（恰 1 位选中直接匹配、多人选未终选按面试分自动分配），推进过「调剂分流」时自动收尾（流转下一轮或进入待选池）。
- 页面展示每次推进的自动匹配统计（自动匹配数、超时分配数、进入待选池数、流转下一轮数）。
- **「重置流程」**：让系统可重复使用，避免整套流程只能跑一次。点击后弹出二次确认框，必须手动输入 `RESET` 才能执行；执行后：
  - 物理清空全部事务数据：调剂意愿、学生志愿、面试记录、导师选人、学生终选、分流记录、匹配结果、待选池、名额变动日志（共 9 张表）。
  - 所有轮次恢复「未开始」并清空填报时间；所有阶段恢复「未开始」并清空起止时间与备注。
  - 学生、导师、实训室、账号、系统配置等基础数据**不受影响**，重置后可直接重新「开始轮次」开始新一轮完整流程。
- 接口：`GET /admin/flow/overview`、`POST /admin/flow/rounds/{id}/start`、`POST /admin/flow/rounds/{id}/next-stage`、`POST /admin/flow/reset`（body `{"confirm":"RESET"}`，确认码错误返回 400）

### 4. 统筹调剂
- 分流候选总览：学生、调剂范围（实训室内/全校）、成绩、当前安置状态。
- 「系统统筹」：按面试平均分降序，先实训室内、后全校两级优先安置，返回安置成功数与未安置名单。
- 分流记录查询。
- 接口：`GET /admin/flow/rounds/{id}/diversion/candidates`、`POST .../system-place`、`GET .../diversion/records`

### 5. 待选池
- 列表可按状态筛选（待约谈 / 已约谈 / 已安置），展示未录取原因、经历轮次。
- 约谈登记、人工安置（指定导师 + 备注），安置时校验导师剩余名额。
- 接口：`GET /admin/wait-pool?status=`、`PUT /admin/wait-pool/{studentId}/interview`、`POST /admin/wait-pool/{studentId}/settle`

### 6. 统计导出与系统配置
- 统计接口：`/admin/stats/summary`、`/by-room`、`/by-teacher`、`/by-round`；数据总览页提供 CSV 导出（UTF-8 BOM）。
- 系统配置页：`GET /admin/config`、`PUT /admin/config/{key}`，可调最大志愿数、补录轮数、默认名额、终选超时等，修改后即时生效。

## 六、发现的问题

### 6.1 已修复：教师撤销选人后无法在同一轮重新选择同一学生
- 现象：`DELETE /teacher/picks/{studentId}` 返回成功，列表已为空；随后 `POST /teacher/picks` 选同一学生返回 **409「数据已存在，请勿重复提交」**。
- 原因：`teacher_pick` 表的唯一索引 `uk_round_teacher_student_source` 未排除逻辑删除行；撤销只把 `deleted` 置 1，旧行仍占用唯一键，重新插入冲突。
- 修复方案：为 `teacher_pick` 增加 STORED 生成列 `active_flag`（`deleted=0` 时为 1，`deleted=1` 时为 NULL），并将唯一索引改为 `(round_id, teacher_id, student_id, pick_source, active_flag)`。唯一索引中 NULL 不参与去重，因此历史撤销记录可保留多条，同一时刻仍只允许一条有效记录。
- 代码/脚本改动：
  - `backend/sql/schema.sql` 的 `teacher_pick` 建表语句已同步更新（新库直接生效）。
  - 已有库执行迁移：
    ```sql
    ALTER TABLE teacher_pick
      ADD COLUMN active_flag TINYINT GENERATED ALWAYS AS (IF(deleted = 0, 1, NULL)) STORED,
      DROP INDEX uk_round_teacher_student_source,
      ADD UNIQUE KEY uk_round_teacher_student_source
        (round_id, teacher_id, student_id, pick_source, active_flag);
    ```
  - 主库 `leb-sele` 与测试库 `leb-sele-test` 均已执行迁移；无需改 Java 代码、无需重新打包。
- 回归验证（测试库 + 8081 实例，真实接口）：
  - 首次 `POST /teacher/picks {studentId:8}` → `code=0`
  - `DELETE /teacher/picks/8` → `code=0`
  - 再次 `POST /teacher/picks {studentId:8}` → `code=0`（修复前为 409）
  - 重复选择未撤销的学生仍返回 `code=409`，唯一性约束未被削弱
  - 验证后已恢复测试库状态并停止 8081 实例

### 6.2 已处理：主库演示数据状态不一致
- 原问题：`selection_round` 三轮 `status` 均为 0（未开始），但 `flow_stage` 各阶段均为 2（已结束），后端因此判定「无当前轮次」，写操作全部返回 409。
- 处理方式（2026-11-16）：
  - 先备份主库：`D:\bangstudydownloads\apache-maven-3.10.0\clone\leb-sele-backup-20261116.sql`。
  - 清空事务数据：`adjustment_wish`、`student_choice`、`interview`、`teacher_pick`、`student_final_choice`、`diversion_record`、`match_result`、`wait_pool`、`teacher_quota_log`。
  - 重置三轮状态为「未开始」、阶段状态为「未开始」，清理轮次时间字段。
  - 通过管理接口 `POST /admin/flow/rounds/1/start` 开启第一轮，当前阶段为「志愿填报（进行中）」。
- 处理结果：学生状态恢复为「未填报志愿」，已匹配 0 / 未匹配 20，待选池 0，教师名额全部可用（如 T-SD01 15/15），可正常开展全流程演示与操作。

### 6.3 接口文档与实现的小差异
